NAME
     tunefs_minixfs – change the settings of a MINIX file system

SYNOPSIS
     tunefs_minixfs [-fN] [-B le | be] [-c clean | dirty] [-e 0 | 1]
                    [-l 14 | 30] [-m minix | linux | bytes]
                    [-M size:heads:side] [-s blocks [-k]] image

DESCRIPTION
     tunefs_minixfs changes the settings of the MINIX file system in image;
     see minixfs(5).  Without options it prints them: the byte order, the name
     length, the size in blocks, whether the file system is marked clean, the
     maximum file size with the one MINIX works out, and the bits of the maps
     past the last inode or zone.  Each change is printed as the old and the
     new value.  The byte order is changed first, then the name length, then
     the size.  The image is locked with fcntl(2) while it is written, and one
     that another program holds is refused.

     The options are:

     -N      Print what the other options would change, and write nothing.

     -B le | be
             Store every number of the file system in the other byte order,
             little-endian as on the PC or big-endian as on the Atari ST and
             the Amiga: the super block, the words of the bit maps, the
             inodes, the indirect zones and the inode numbers of directory
             entries.  Everything is read before anything is written.

     -l 14 | 30
             Give a V1 or V2 file system names of 14 characters, as in MINIX,
             or 30, the extension of Linux: the magic number changes, and
             every directory is written anew with entries of the new size.
             Every directory is read, every name checked and the zones counted
             before anything is written; names too long for 14 characters are
             all listed, and then nothing changes, as when the larger
             directories would not fit.

     -s blocks
             Grow or shrink the file system, and the image file with it unless
             -k is given or the image is a device, to blocks blocks, cut down
             to whole zones.  Used zones are relocated as needed, and growing
             the zone map may require additional space for relocating metadata
             and data.  If there is insufficient space, resizing makes no
             changes.  Earlier changes may remain when combined with -l; see
             CAVEATS.  Shrinking keeps the zone map's block count, which
             fsck_minixfs -w may report as excessive.  If the image size is
             retained, it must already hold the requested size.  A device
             whose size cannot be determined cannot be grown.

     -k      With -s, keep the size of the image file: the file system shrinks
             inside it and leaves what is past its new end as it was, or grows
             as far as the file holds.

     -f      Change a file system that is not marked clean with -B, -l and -s
             all the same; see CAVEATS.

     -c clean | dirty
             Mark the file system clean or dirty: in V1 and V2 in the state
             field that Linux keeps, in V3 in the flags of MINIX 3, which
             mounts a file system that is not clean read-only, and in Minix-
             vmd in its flags.

     -e 0 | 1
             Set the bits of each map past the last inode or zone to 0, as the
             mkfs of MINIX leaves them, or 1, as that of Linux sets them.

     -m minix | linux | bytes
             Set the maximum file size in the super block to what MINIX works
             out from the zones that the double indirect zone reaches, as
             newfs_minixfs(8) writes it by default, to what mkfs.minix of
             Linux writes, or to bytes, from 1 to 2147483647.  Linux and the
             tools of this package keep files to it; see CAVEATS in
             minixfs(5).  A size below that of the largest file is refused,
             and nothing changes.

     -M size:heads:side
             Modify an image containing the file system on one disk side.  See
             minixfs(1) for the track layout.  Its size cannot change.

EXIT STATUS
     tunefs_minixfs exits with 0 on success, 1 if anything failed, and 2 for a
     usage error.

EXAMPLES
     Turn a disk of the Atari ST into one for the PC, with the names of Linux:

           $ tunefs_minixfs -B le -l 30 atari.img

     Double the size of an image:

           $ tunefs_minixfs -s 2880 floppy.img

AUTHORS

CAVEATS
     Before using -B, -l or -s, unmount the image, check it with
     fsck_minixfs(8) and keep a backup.  Interruption can leave the conversion
     incomplete.  These options require a clean image unless -f is given;
     forcing a change does not make it safe on a mounted file system.
     fsck_minixfs -y marks a consistent image clean, including V1 and V2
     images created by MINIX without a clean flag.

     Invalid requests are rejected before writing.  When combining -l and -s,
     resizing may fail because the converted directories change the space
     required.  The error reports any changes already applied.

     -B and -l do not apply to Minix-vmd.
