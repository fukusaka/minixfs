NAME
     minixfs – MINIX ファイルシステムの形式

DESCRIPTION
     MINIX のファイルシステムには V1・V2・V3 の 3 つの版があります。 Linux は
     V1 と V2 に、30 文字の名前と superblock の状態欄を加え、Minix-vmd
     は、superblock のフラグと、項目が名前の長さに合わせて伸び縮みする flex
     ディレクトリを加えました。 各コマンドは両方のバイト順に対応します。
     操作と制限は各コマンドの man を参照してください。

   配置
     ファイルシステムはブロックの並びです。 ブロックは V1 と V2 では 1024
     バイトで、V3 では superblock が示す大きさです。

           ブロック               中身
           0                      ブートブロック
           1                      superblock（どの版でもバイト 1024 から）
           2                      inode マップ（imap ブロック数）
           2 + imap ブロック数    zone マップ（zmap ブロック数）
           マップの後             inode 表
           最初のデータ zone      データ zone（末尾まで）

     データは、2 の zone の大きさ乗ブロックの zone に入れます。 zone
     番号はファイルシステムの先頭から数え、最初のデータ zone
     より前の番号はファイルでは使いません。

   superblock
     数値はすべて、ファイルシステムを作った機械のバイト順で書きます。 PC
     ではリトルエンディアン、68000 の機械（Atari
     ST、Amiga、Macintosh）ではビッグエンディアンです。
     マジック番号から、版、名前の長さ、バイト順がわかります。

           マジック番号    版      名前    出どころ
           0x137f          V1      14      MINIX
           0x137f          V1      14、60  Minix-vmd
           0x138f          V1      30      Linux
           0x2468          V2      14      MINIX
           0x2468          V2      14、60  Minix-vmd
           0x2478          V2      30      Linux
           0x4d5a          V3      60      MINIX 3

     V1 と V2 は同じ superblock を使い、次のバイト位置に次のものがあります。

           位置    バイト    欄
           0       2         inode 数
           2       2         zone 数（V1）
           4       2         inode マップのブロック数
           6       2         zone マップのブロック数
           8       2         最初のデータ zone
           10      2         1 zone のブロック数の log2
           12      4         最大ファイルサイズ
           16      2         マジック番号
           18      2         0
           20      4         zone 数（V2）

     Linux と Minix-vmd もこの superblock を使い、次の所だけが違います。
     •   Linux は、18 に状態欄 s_state（1 正常にアンマウント、2
         エラーあり）を持ちます。
     •   Minix-vmd は、zone の大きさをバイト 10 だけに持ち、バイト 11
         にフラグ（0x01 flex ディレクトリ、0x02 clean）を持ちます。 clean
         フラグを使うときは、18 に 0x7f と 0x13 を持ちます。 Minix-vmd
         を参照してください。

     V3 の superblock は、独自の配置です。

           位置    バイト    欄
           0       4         inode 数
           6       2         inode マップのブロック数
           8       2         zone マップのブロック数
           10      2         最初のデータ zone（収まらなければ 0
                             で、そのときは inode 表の直後）
           12      2         1 zone のブロック数の log2
           14      2         フラグ（0x0001 clean、0xff00
                             のビットはマウントに理解が必要）
           16      4         最大ファイルサイズ
           20      4         zone 数
           24      2         マジック番号
           28      2         ブロックサイズ

     MINIX 3 は、clean
     の印のないファイルシステムを読み出し専用でマウントします。
     最大ファイルサイズはファイルの大きさを制限します。 MINIX は二重間接 zone
     の届く範囲からこれを計算し、Linux は V2 と V3 に 2147483647 を書きます。

   ビットマップ
     inode マップのビット i は、inode i が使用中なら立ちます。 zone
     マップのビット i は、zone「最初のデータ zone + i -
     1」が使用中なら立ちます。 どちらのマップもビット 0
     は使わず、常に立てておきます。 マップは、V1 と V2 では 16 ビット、V3 では
     32 ビットの語の配列で、ファイルシステムのバイト順で書き、語のビット 0
     が最下位です。 最後の inode や zone より後ろのビットは、MINIX と Minix-
     vmd の mkfs は 0、Linux の mkfs.minix は 1 にします。 MINIX 2.0.4、Minix-
     vmd 1.7.0、MINIX 3 の fsck は1 を足りない inode や zone
     として報告し、Linux のカーネルは0 を空きに数えて、マップが埋まると1
     つずつ立てます。 MINIX 1.3 と 1.6.25 の fsck とfsck.minix
     はここを見ません。

   inode
     inode 1 がルートディレクトリで、inode 0 はありません。 V1 の inode は 32
     バイトです。

           位置    バイト    欄
           0       2         モード（型とアクセス許可）
           2       2         所有者
           4       4         大きさ
           8       4         更新時刻
           12      1         グループ
           13      1         リンク数
           14      9 × 2     zone（直接 7、一重間接、二重間接）

     V2 と V3 の inode は 64 バイトです。

           位置    バイト    欄
           0       2         モード
           2       2         リンク数
           4       2         所有者
           6       2         グループ
           8       4         大きさ
           12      4         アクセス時刻
           16      4         更新時刻
           20      4         状態変更時刻
           24      10 × 4    zone（直接 7、一重・二重・三重間接）

     時刻は紀元からの秒数です。 モードの型は stat(2) と同じで、0100000
     通常ファイル、0040000 ディレクトリ、0120000 シンボリックリンク、0020000
     キャラクタデバイス、0060000 ブロックデバイス、0010000 FIFO、0140000
     ソケットです。 空き inode のモードは 0 です。

     zone の欄の 0 は穴で、ゼロとして読めます。 間接 zone
     は、その最初のブロックに zone 番号を並べたもので、番号は V1 では 16
     ビット、V2 と V3 では 32 ビットです。 MINIX は三重間接 zone
     を使わず、二重間接 zone が届く範囲の zone だけを辿ります。 Linux
     とこのパッケージは三重間接 zone も使います。 三重間接 zone
     を使わないとき、ファイルの大きさは次の値までで、MINIX の mkfs
     はこの値を最大ファイルサイズとして書きます。 2 の k 乗ブロックの zone
     では、2 の k 乗倍まで届き、上限は 2147483647 です。

           種類                           バイト
           V1                             268966912
           V2・V3（1024 バイトのブロック）
                                          67378176
           V3（2048 バイトのブロック）    537933824
           V3（4096 バイト以上のブロック）
                                          2147483647

     デバイスは、最初の zone の欄にデバイス番号（メジャー番号 × 256 +
     マイナー番号）を持ちます。 シンボリックリンクは、リンク先の文字列を NUL
     なしでデータに持ちます。

   ディレクトリ
     ディレクトリは項目を並べたファイルです。 最初の項目は ‘.’, 2 番目は ‘..’
     で、ルートの ‘..’ はルート自身です。 項目の種類は、マジック番号と、Minix-
     vmd では superblock のバイト 11 の flex フラグ 0x01 で決まります。
     位置は項目の先頭からのバイト数です。

           種類              マジック番号      大きさ    inode   名前
           MINIX             0x137f, 0x2468    16        0–1     2–15
           Linux             0x138f, 0x2478    32        0–1     2–31
           MINIX 3           0x4d5a            64        0–3     4–63
           Minix-vmd flex    0x137f, 0x2468    8–64      0–1     3–末尾

     MINIX、Linux、MINIX 3 では、どの項目も表の大きさです。
     名前は欄の終わりまで NUL で埋め、欄を埋める名前は NUL を持ちません。

     flex の項目は 8 バイトのスロット 1〜8 個です。

           位置       バイト    欄
           0          2         inode 番号
           2          1         最初のスロットの後のスロット数（0〜7）
           3          5         名前の最初の 5 バイト
           8〜末尾    8 ずつ    名前の残りと、それに続く NUL

     n 文字の名前は 1 + (n + 3) / 8
     個（割り算は切り捨て）のスロットを使い、NUL が少なくとも 1 つ入ります。
     名前は最後のスロットの終わりまで NUL で埋めます。 項目は 1
     つのブロックの中に収まります。

     inode 番号が 0 の項目は空きです。 Minix-vmd は、flex
     の項目を消すときは各スロットのバイト 0〜2 を 0 にし、項目を足すときは 1
     つのブロックの中で必要な数の空きスロットが続く最初の場所に、なければ新しいブロックに置きます。

   Minix-vmd
     Philip Homburg と Kees Bot による MINIX の派生 Minix-vmd は、MINIX
     のマジック番号で V1 と V2 を書きます。 superblock と flex
     ディレクトリは上で説明したとおりです。 clean フラグは、superblock
     のバイト 18 と 19 が 0x7f と 0x13 のときだけディスクに保ちます。
     この値は、mkfs が flex ディレクトリのファイルシステムを作るときに書き、
     ‘fsck -c’ が書いたり消したりします。 このパッケージの道具は、この値で
     Minix-vmd を見分け、値のないファイルシステムは MINIX
     のものとして読みます。

   システム
     各システムが読み書きする種類は次のとおりです。

           システム                 種類
           MINIX 1.0〜1.5           MINIX の V1
           MINIX 1.6.23〜2.0.4      MINIX の V1・V2
           Minix-vmd 1.7.0          MINIX の V1・V2 と flex ディレクトリ
           MINIX 3〜3.2.1           MINIX の V1・V2・V3
           MINIX 3.3.0              V3
           3.3.0 より後の MINIX 3   1 ブロックの zone の V3
           Linux                    MINIX と Linux の V1・V2、2.6.21 からは V3
           このパッケージ           すべて

     30 文字名に対応するのは Linux と本ツール群だけです。 1.6.23 以降の MINIX
     は、V1 と V2 をどちらのバイト順でも読み、Linux と、V3 の MINIX 3
     は、その機械のバイト順のものだけを読みます。 Linux は、V3
     のブロックをページの大きさ（PC では 4096）までしか受け付けません。 MINIX
     3 の mkfs は 3.2.1 から V3 だけを作り、Linux の mkfs（util-linux の
     mkfs.minix）は 1994 年から V2 を、2.20 から V3 を作ります。

   ディスクの片面のイメージ
     片面に書かれ、両面として読み取られたディスク（Atari ST
     のものの一部など）は、イメージのトラック 1
     つおきにファイルシステムを持ちます。 道具の -M size:heads:side
     オプションでこうしたイメージを読めます。 minixfs(1) を参照してください。

HISTORY
     年・版は確認できたソースに基づき、初出とは限りません。
     年はリリース年、1994 年と 2015 年はソース変更年です。

     1987  V1 は、書籍の初版の MINIX 1.0 のファイルシステムです。

     1991  Linux は、最初の版の 0.01 から V1 を使います。 V1
           をビッグエンディアンで書く 68000 への移植版、Atari
           ST・Amiga・Macintosh の MINIX 1.5 が配布されます。

     1992  32 ビットの zone 番号とアクセス時刻・状態変更時刻を持つ V2
           が、MINIX 1.6.23 に入ります。
           この版は、バイト順の違う機械で作ったファイルシステムも読みます。
           そのマジック番号はバイトが入れ替わって見えます（0x137f なら
           0x7f13）。

     1993  Linux は、0.99.7 までに 30 文字の名前（マジック番号
           0x138f）を、0.99.15 までに状態欄を加えます。

     1994  Linux の mkfs.minix が V2 を作るようになります。

     1996  Linux は、2.0 までに V2 と、30 文字の名前の V2（マジック番号
           0x2478）を読むようになり、MINIX が使わない三重間接 zone
           も使います。 MINIX 1.7 を元にした Minix-vmd 1.7.0 は、superblock
           のフラグと flex ディレクトリを持ちます。 Minix-vmd
           の公開版はこれより後にはありません。

     1997  V2 は、書籍の第 2 版の MINIX 2.0 のファイルシステムです。

     2005  ほかの大きさのブロックと 60 文字の名前を持つ V3 は、MINIX 3
           のファイルシステムです。

     2007  Linux は、2.6.21 から V3 を読みます。

     2010  MINIX 3.1.6 は、V3 の最初のデータ zone が 16 ビットに収まらないとき
           0 を書き、inode 表の直後とみなします。

     2011  util-linux の mkfs.minix が、2.20 から V3 を作ります。

     2012  MINIX 3.2.0 は、V3 のフラグに clean の印を持ちます。

     2013  MINIX 3.2.1 の mkfs は V3 だけを作ります。 3.0〜3.2.0 の mkfs は V1
           と V2 も作りました。

     2014  MINIX 3.3.0 は V3 だけを読みます。

     2015  3.3.0 より後の MINIX 3 は、複数ブロックの zone を拒みます。

CAVEATS
     MINIX は、ファイルのうち二重間接 zone が届く範囲より先を、エラーなしで 0
     として読みます。 V2 と V3 では、Linux とこのパッケージは三重間接 zone
     を使って、superblock の最大ファイルサイズまでその先を書きます。 Linux の
     mkfs.minix は、この値を 2147483647 にし、 newfs_minixfs(8) も -m linux
     ではそうします。 そのため、1024 バイトのブロックの V2 で 67378176
     バイトを超えるファイルは、MINIX では全部は読めません。 ‘tunefs_minixfs -m
     minix’ で、どちらも MINIX が読める範囲に抑えられます。

     3.3.0 より後の MINIX 3 は、 newfs_minixfs(8) の -z で作る、複数ブロックの
     zone を持つファイルシステムをマウントしません。

BUGS
     ‘fsck -c’ で clean フラグを使わなくした、flex ディレクトリを持つ Minix-
     vmd のファイルシステムは、0x7f と 0x13 のバイトを持たないので、MINIX
     のファイルシステムでないとして拒みます。 MINIX
     のものとして読むと、フラグのために zone の大きさが大きすぎるためです。
