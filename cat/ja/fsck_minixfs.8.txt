FSCK_MINIXFS(8)             System Manager's Manual            FSCK_MINIXFS(8)

NAME
     fsck_minixfs – MINIX ファイルシステムを検査し、修復する

SYNOPSIS
     fsck_minixfs [-lwy] [-e 0 | 1] [-M size:heads:side] image

DESCRIPTION
     fsck_minixfs は、 image の MINIX ファイルシステムを検査します。
     版とバイト順は問わず、Minix-vmd のものも扱います。 形式は minixfs(5)
     を参照してください。 検査するのは次のものです。

     •   superblock：意味のある最大ファイルサイズか、イメージにファイルシステム全体が入っているか（デバイスの大きさが分かるとき）、V1
         と V2 の状態欄に Linux がエラーを記録していないか。

     •   ディレクトリ項目：inode 番号が範囲内か、空き inode や型の正しくない
         inode を指していないか、名前が空でなく ‘/’ を含まないか、 ‘.’ と ‘..’
         が先頭にあってディレクトリ自身と親を指しているか、同じディレクトリが複数のディレクトリに載っていないか。

     •   inode：大きさが zone
         の届く範囲にあるか、ディレクトリの大きさが項目の整数倍か、zone
         番号がデータ領域の中か、2 つのファイルが同じ zone
         を使っていないか、デバイスファイルがデバイス番号のほかに zone
         番号を持っていないか、シンボリックリンクが空でなく、Linux
         が書く長さを超えず、途中に NUL がないか。

     •   各 inode を指す項目の数とリンク数、未参照
         inode（使用中なのに、どのディレクトリにも名前がない inode）、2
         つのビットマップ、各ビットマップのビット
         0（使わないが立っていなければならない）。

     ディレクトリツリーの深さやディレクトリのループで検査が止まることはありません。
     問題は 1 件ずつ 1 行で表示し、最後に使用中の inode と zone
     の数と、見つけた問題の数をまとめて表示します。 clean
     の印がないファイルシステムはその旨を示しますが、それ自体は問題としません。
     V1 と V2 では、Linux が印を置く語を MINIX は 0 のままにするからです。

     -y がなければ、イメージは読むだけです。

     オプションは次のとおりです。

     -y      問題を、直せるところで直します。 不正な項目は消します。 ‘.’ と
             ‘..’ は正しい先を指すように直し、なければ書き戻します。
             その場所をふさぐ項目は移し、ディレクトリに zone
             がなければ割り当てます。 データ領域の外の zone 番号と、2
             つ目以降の zone の使用は消します。 大きさは、zone
             の届く範囲、項目の整数倍、シンボリックリンクの文字列に切り詰めます。
             リンク数とビットマップを修正し、未参照 inode を解放します。
             superblock の最大ファイルサイズが 0 か 2147483647
             を超えるときは、MINIX が計算する値にします。
             ディレクトリでないルートと、ファイルシステムより短いイメージはそのままにします。
             各問題の後に ‘(repaired)’ か ‘(not repaired)’ を付けます。
             その後もう一度検査し、何も残っていなければ clean の印を付けます。
             V1 と V2 では Linux と同じ形で、V3 では MINIX 3 の clean
             フラグで印を付けます。 MINIX 3
             は、この印のないファイルシステムを読み出し専用でマウントします。
             問題が残れば、エラーありの印を付けます。 書き込む間はイメージを
             fcntl(2)
             でロックし、ほかのプログラムがロックしているイメージは拒みます。

     -l      -y と一緒に使い、未参照 inode を、解放せずに lost+found
             へつなぎます。 名前は ‘#’ と inode
             番号で、ディレクトリならその下のディレクトリツリーごとつなぎます。
             lost+found がなければ作ります。 MINIX と Linux には lost+found
             がなく、その fsck はこうした inode
             を解放するので、これは既定にしていません。

     -e 0 | 1
             各ビットマップの、最後の inode や zone より後ろのビットが 0 か 1
             かを検査します。 -y と一緒ならその値にそろえます。
             この指定がなければ、どちらも問題にしません。 minixfs(5)
             を参照してください。

     -w      MINIX 3 の fsck
             が警告する事柄を、問題ではない警告として示します。
             マップに必要より多いブロック、inode
             表の直後より後ろにある最初のデータ zone、MINIX
             の計算と違う最大ファイルサイズ、256 ブロックを超える zone です。
             最大ファイルサイズを超えるファイルも示します。 Linux
             はその先のブロックを読みません。

     -M size:heads:side
             片面にファイルシステムがあるディスクイメージを検査します。
             トラックの指定方法は minixfs(1) を参照してください。 -y
             では指定した面だけを修復します。

EXIT STATUS
     fsck_minixfs は、ファイルシステムに矛盾がなければ（ -y
     なら修復の後で）0、問題が残れば 1、使い方の誤りなら
     2、イメージをまったく検査できなければ 3 で終了します。

EXAMPLES
           $ fsck_minixfs root.img
           $ fsck_minixfs -y -l usr.img
