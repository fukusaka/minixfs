NEWFS_MINIXFS(8)            System Manager's Manual           NEWFS_MINIXFS(8)

NAME
     newfs_minixfs – MINIX ファイルシステムを空で、またはディレクトリから作る

SYNOPSIS
     newfs_minixfs -V version [-N] [-B le | be] [-b block-size] [-d directory
                   [-F specfile [-P dbdir [-x]]] [-o uid:gid]] [-e 0 | 1]
                   [-i inodes] [-l name-length | flex]
                   [-m minix | linux | bytes] [-s blocks] [-t time]
                   [-z log-zone-size] image

DESCRIPTION
     newfs_minixfs は、ファイルまたはデバイス image に、版 1・2・3 の MINIX
     ファイルシステムか、Minix-vmd のファイルシステムを作ります。 形式は
     minixfs(5) を参照してください。 中身は空のルートディレクトリか、 -d
     を付ければディレクトリの写しです。 image の先頭 1024
     バイトはブートブロックの場所なので、手を付けません。 ファイルシステムには
     clean の印を付けます。 書き込む間はイメージを fcntl(2)
     でロックし、ほかのプログラムがロックしているイメージは拒みます。

     大きさは -s で決めます。
     このときイメージファイルを作るか、その大きさに切り詰めます。 -s
     がなければ、既存のファイルの大きさを使います。 -d
     を付けてどちらもなければ、ディレクトリツリーがちょうど収まる大きさで作ります。

     オプションは次のとおりです。

     -V version
             ファイルシステムの版で、1・2・3 のどれかです。 必ず指定します。

     -N      配置を表示するだけで、何も書きません。 -d
             を付ければ、ディレクトリツリーに必要なものも表示します。

     -B le | be
             バイト順です。 PC と同じリトルエンディアン（既定）か、Atari
             ST・Amiga・Macintosh と同じビッグエンディアンです。

     -b block-size
             V3 のブロックサイズで、1024 の倍数で 32768 までです。
             既定は、MINIX 3 がマウントできる最小の 4096 です。 V1 と V2
             のブロックは常に 1024 バイトです。

     -d directory
             directory をファイルシステムに写します。
             ファイル、ディレクトリ、シンボリックリンク、デバイス、FIFO
             を、モード・所有者・時刻とともに、名前の順に入れます。
             名前順に配置するため、同じ内容と属性から同じイメージを作れます。
             ハードリンクはリンクのまま、すべてゼロのブロックは穴のままにします。
             シンボリックリンクのモードは、MINIX と Linux と同じく 0777
             にします。 ルートディレクトリは、 directory
             自身のモード・所有者・時刻を受け継ぎます。
             ソケットは警告を出して除きます。 既存のデバイスファイルは root
             権限なしで取り込めます。

             書き込む前にすべてを確かめます。
             ファイルシステムに入らない長さの名前、大きすぎる所有者・グループ・デバイス番号・リンク数、容量です。
             容量は穴もデータとして数えます。
             問題はすべて表示し、何も書きません。 -i
             がなければ、ディレクトリツリーに足りるだけの inode を用意します。

     -F specfile
             mtree(8) の指定ファイル specfile を、 NetBSD の makefs(8) の -F
             と同じように読みます。 階層形式と、ビルドが書く METALOG
             のようなフルパス形式の両方を読めます。
             項目は、指す対象の型・モード・所有者・グループ・時刻・リンク先・デバイス番号を定め、
             directory のファイルの値を上書きします。 directory
             にないものは、項目のとおりに作ります。
             このとき項目には、少なくとも型・モード・所有者・グループが要り、リンクならリンク先、デバイスならデバイス番号も要ります。
             通常ファイルは空で作ります。 optional の付いた項目は、 directory
             になければ除きます。 型が directory
             のファイルと食い違えば誤りです。 使うキーワードは type, mode （8
             進）、 uid, uname, gid, gname, time, link, device, optional
             です。 チェックサム、 size, flags, tags などは読み飛ばします。
             /set, /unset, 行の継続、 vis(3) のエスケープを解釈します。
             パターンを含む名前は扱いません。

     -P dbdir
             -F のユーザー名を、システムのものではなく、ディレクトリ dbdir の
             master.passwd か passwd で引きます。
             グループ名は同じディレクトリの group で引きます。

     -x      -F の指定ファイルにあるものだけを写します。

     -o uid:gid
             ディレクトリツリーのすべてのファイルに、所有者 uid とグループ gid
             を与えます。 どちらも数値です。 V1 の inode はグループを 1
             バイトで持つので、255 を超えるグループのあるディレクトリツリーを
             V1 にするにはこれが要ります。

     -e 0 | 1
             マップの最後の inode や zone より後ろのビットを、MINIX と同じ 0
             か、Linux と同じ 1 にします。 既定は、30 文字の名前では 1、ほかは
             0 です。 minixfs(5) を参照してください。

     -i inodes
             inode の数です。 inode 表のブロックが埋まるまで切り上げます。
             既定はおよそ 3 ブロックに 1 つで、 -d
             のディレクトリツリーがそれより多く要ればその数にします。

     -l name-length | flex
             V1 と V2 の名前の長さです。 MINIX と同じ 14（既定）か、Linux
             の拡張の 30 で、30 のほうは専用のマジック番号を持ちます。 V3
             の名前は常に 60 文字です。 flex は、60 文字までの名前を持つ flex
             ディレクトリの、Minix-vmd の V1 か V2
             のファイルシステムを作ります。 Minix-vmd の mkfs
             と同じく、マジック番号は 14 文字のもの、superblock は Minix-vmd
             のものにし、マップの最後の inode や zone より後ろのビットは 0
             のままにします。

     -m minix | linux | bytes
             superblock の最大ファイルサイズです。 minix は、二重間接 zone
             の届く範囲から MINIX が計算する値で、既定です。 MINIX
             がどのファイルも全部読めます。 linux は Linux の mkfs.minix
             が書く値で、V2 と V3 では 2147483647 です。 bytes は 1 から
             2147483647 までの数値です。 Linux
             とこのパッケージの道具は、ファイルをこの大きさまでに抑えます。
             minixfs(5) を参照してください。

     -s blocks
             ブロック単位の大きさです。

     -t time
             ルートディレクトリの時刻で、紀元からの秒数です。
             毎回同じイメージを作りたいときに使います。

     -z log-zone-size
             zone を 2 の log-zone-size 乗ブロックにします。 既定は 0、つまり
             1 ブロックです。 3.3.0 より後の MINIX 3 は、複数ブロックの zone
             を持つファイルシステムをマウントしません。 minixfs(5)
             を参照してください。

EXIT STATUS
     newfs_minixfs は、成功すれば 0、ファイルシステムを作れなければ
     1、使い方の誤りなら 2 で終了します。

EXAMPLES
     360K の V1 フロッピーと、64 メガバイトの V3 イメージを作ります。

           $ newfs_minixfs -V 1 -s 360 floppy.img
           $ newfs_minixfs -V 3 -s 16384 disk.img

     ディレクトリから、ちょうど収まる大きさの、root 所有のイメージを作ります。

           $ newfs_minixfs -V 2 -d tree -o 0:0 tree.img

     MINIX のビルドから、METALOG
     の所有者・モード・デバイスを付けてイメージを作ります。

           $ newfs_minixfs -V 3 -d destdir -F destdir/METALOG \
               -P destdir/etc -x usr.img
