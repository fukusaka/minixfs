NAME
     tunefs_minixfs – MINIX ファイルシステムの設定を変える

SYNOPSIS
     tunefs_minixfs [-fN] [-B le | be] [-c clean | dirty] [-e 0 | 1]
                    [-l 14 | 30] [-m minix | linux | bytes]
                    [-M size:heads:side] [-s blocks [-k]] image

DESCRIPTION
     tunefs_minixfs は、 image の MINIX ファイルシステムの設定を変えます。
     形式は minixfs(5) を参照してください。
     オプションがなければ設定を表示します。
     表示するのは、バイト順、名前の長さ、ブロック単位の大きさ、clean
     の印の有無、最大ファイルサイズと MINIX が計算する値、マップの最後の inode
     や zone より後ろのビットです。 変更は、古い値と新しい値を並べて示します。
     バイト順を最初に変え、次に名前の長さ、最後に大きさを変えます。
     書き込む間はイメージを fcntl(2)
     でロックし、ほかのプログラムがロックしているイメージは拒みます。

     オプションは次のとおりです。

     -N      ほかのオプションで何が変わるかを示すだけで、何も書きません。

     -B le | be
             ファイルシステムのすべての数値を、PC
             と同じリトルエンディアンか、Atari ST・Amiga
             と同じビッグエンディアンで書き直します。 対象は superblock、V1 と
             V2 のビットマップの語、inode、間接 zone、ディレクトリ項目の inode
             番号です。 V3
             のビットマップはどちらのバイト順でもバイトの並びなので、そのままです。
             書き込む前にすべてを読みます。

     -l 14 | 30
             V1 か V2 のファイルシステムの名前を、MINIX と同じ 14
             文字か、Linux の拡張の 30 文字にします。
             マジック番号が変わり、すべてのディレクトリを新しい大きさの項目で書き直します。
             書き込む前に、すべてのディレクトリを読み、すべての名前を確かめ、zone
             を数えます。 14
             文字に収まらない名前はすべて示し、そのときは何も変えません。
             大きくなるディレクトリが収まらないときも何も変えません。

     -s blocks
             ファイルシステムと、 -k
             がなくイメージがデバイスでなければイメージファイルも、 blocks
             ブロック（zone の整数倍に切り下げ）に広げるか縮めます。 使用中の
             zone は必要に応じて移動します。 zone
             マップの拡張には、メタデータとデータの移動に追加容量が必要な場合があります。
             容量不足なら、容量変更は何も書き換えずに失敗します。 ただし -l
             との併用では先行する変更が残る場合があります。 CAVEATS
             を参照してください。 縮小時は zone
             マップのブロック数を保持するため、 fsck_minixfs -w
             が過剰なブロックを報告する場合があります。
             イメージ自体の容量を保持する場合、指定容量がすでに収まっている必要があります。
             容量を取得できないデバイスは拡張できません。

     -k      -s で、イメージファイルの大きさを保ちます。
             ファイルシステムはその中で縮んで新しい末尾より後ろをそのまま残すか、ファイルの大きさまで広がります。

     -f      clean の印がないファイルシステムでも、 -B, -l, -s で変更します。
             CAVEATS を参照してください。

     -c clean | dirty
             ファイルシステムに clean か dirty の印を付けます。 V1 と V2 では
             Linux の状態欄に、V3 では MINIX 3 のフラグに、Minix-vmd
             ではそのフラグに付けます。 MINIX 3 は clean
             でないファイルシステムを読み出し専用でマウントします。

     -e 0 | 1
             各マップの、最後の inode や zone より後ろのビットを、MINIX 2
             以降の mkfs と同じ 0 か、MINIX 1 と Linux の mkfs と同じ 1
             にします。 minixfs(5) を参照してください。

     -m minix | linux | bytes
             superblock の最大ファイルサイズを変えます。 minix は二重間接 zone
             の届く範囲から MINIX が計算する値、 linux は Linux の mkfs.minix
             が書く値、 bytes は 1 から 2147483647 までの数値です。 Linux
             とこのパッケージの道具は、ファイルをこの大きさまでに抑えます。
             minixfs(5) の CAVEATS を参照してください。
             最も大きいファイルより小さい値は拒み、何も変えません。

     -M size:heads:side
             片面にファイルシステムがあるディスクイメージを変更します。
             トラックの指定方法は minixfs(1) を参照してください。
             容量は変更できません。

EXIT STATUS
     tunefs_minixfs は、成功すれば 0、何かに失敗すれば 1、使い方の誤りなら 2
     で終了します。

EXAMPLES
     Atari ST のディスクを、Linux の名前の長さで PC 用にします。

           $ tunefs_minixfs -B le -l 30 atari.img

     イメージの大きさを倍にします。

           $ tunefs_minixfs -s 2880 floppy.img

CAVEATS
     -B, -l, -s を使う前に、アンマウントし、 fsck_minixfs(8)
     で検査してバックアップを取ってください。
     中断すると変換途中の状態が残ります。 これらのオプションは、 -f がなければ
     clean でないイメージを拒みます。
     強制指定しても、マウント中の変更は安全ではありません。 fsck_minixfs -y
     は、矛盾のないイメージに clean の印を付けます。 MINIX
     が印を付けずに作った V1・V2 イメージも対象です。

     不正な指定は書き込み前に拒みます。 ただし -l と -s
     の併用では、ディレクトリ変換で必要容量が変わり、容量変更が失敗する場合があります。
     その場合は、適用済みの変更をエラーとともに示します。

     -B と -l は Minix-vmd を拒みます。 flex ディレクトリとの間で移すには、
     dump_minixfs(8) でダンプし、 newfs_minixfs(8) で作ったファイルシステムに
     restore_minixfs(8) でリストアします。
