NAME
     newfs_minixfs – make a MINIX file system, empty or from a directory

SYNOPSIS
     newfs_minixfs -V version [-N] [-B le | be] [-b block-size] [-d directory
                   [-F specfile [-P dbdir [-x]]] [-o uid:gid]] [-e 0 | 1]
                   [-i inodes] [-l name-length | flex]
                   [-m minix | linux | bytes] [-s blocks] [-t time] [-W bits]
                   [-z log-zone-size] image

DESCRIPTION
     newfs_minixfs makes a MINIX file system of version 1, 2 or 3, or one of
     Minix-vmd, in the file or device image; see minixfs(5).  It holds an
     empty root directory or, with -d, a copy of a directory.  The first 1024
     bytes of image, where a boot block may be, are left alone.  The file
     system is marked clean.  The image is locked with fcntl(2) while it is
     written, and one that another program holds is refused.

     The size comes from -s, which also makes the image file or cuts it to
     that size, or else from the size of an existing file.  With -d and
     neither, the image is made just large enough for the tree.

     The options are:

     -V version
             The version of the file system: 1, 2 or 3.  It has to be given.

     -N      Print the layout, and with -d what the tree needs, and write
             nothing.

     -B le | be
             Byte order: little-endian (default) or big-endian.

     -b block-size
             The block size of V3, a multiple of 1024 up to 32768; 4096 by
             default, the smallest that MINIX 3 mounts.  V1 and V2 always have
             blocks of 1024 bytes.

     -d directory
             Copy the directory tree in name order, preserving modes, owners,
             times and hard links; blocks of zeros become holes.  The image
             root inherits the source directory's attributes.  Symbolic links
             use mode 0777; sockets are skipped with a warning.  Device files
             can be copied without root privileges.

             Before writing, check name lengths, IDs, device numbers, link
             counts and capacity, counting holes as data.  Report all problems
             and write nothing if any are found.  Unless -i is given, allocate
             enough inodes for the tree.

     -F specfile
             Apply an mtree(8) specification in hierarchical or full-path
             (METALOG) form.  Entries override the source files' attributes; a
             type mismatch is an error.  Missing files are created unless
             marked optional.  Creation requires type, mode, owner and group,
             plus a symbolic link target or device number where applicable;
             regular files are created empty.

             Supported keywords are type, mode (octal), uid, uname, gid,
             gname, time, link, device and optional.  Checksums, size, flags,
             tags and other keywords are ignored.  /set, /unset, continued
             lines and vis(3) escapes are supported; name patterns are not.

     -P dbdir
             Look up the user names of -F in master.passwd or passwd, and the
             group names in group, of the directory dbdir, rather than in
             those of the system.

     -x      Copy only what the specification of -F names.

     -o uid:gid
             Give every file of the tree the owner uid and the group gid,
             numbers both.  A V1 inode keeps its group in one byte, so a tree
             with groups above 255 needs this in V1.

     -e 0 | 1
             The bits of the maps past the last inode and zone: 0, as MINIX 2
             and later leave them, or 1, as MINIX 1 and Linux set them; see
             minixfs(5).  The default is 1 for names of 30 characters and 0
             otherwise.

     -i inodes
             The number of inodes, rounded up to fill the blocks of the inode
             table; by default one for about every three blocks, or more if
             the tree of -d needs them.

     -l name-length | flex
             Select the V1 or V2 directory format: 14-character MINIX names
             (default), 30-character Linux names, or flex for Minix-vmd names
             of up to 60 characters.  V3 always uses 60-character names.
             Format details are in minixfs(5); map padding defaults are
             described under -e.

     -m minix | linux | bytes
             Set the maximum file size: minix uses the range reachable through
             double indirect zones; linux uses Linux's limit (2147483647 bytes
             in V2 and V3); bytes specifies a value from 1 to 2147483647.  The
             default is linux for 30-character names and minix otherwise.
             Linux and these tools enforce this limit.  See minixfs(5) for
             MINIX compatibility restrictions.

     -s blocks
             The size in blocks.

     -t time
             The time of the root directory, in seconds since the Epoch, for
             images that must come out the same each time.

     -W bits
             Write the bit maps of a big-endian file system as words of bits
             bits, 8, 16, 32 or 64, instead of 16 for V1 and V2 and 8 for V3;
             see minixfs(5).

     -z log-zone-size
             A zone of 2 to the power of log-zone-size blocks; 0, one block,
             by default.  MINIX 3 after 3.3.0 does not mount a file system
             with zones of more than one block; see minixfs(5).

EXIT STATUS
     newfs_minixfs exits with 0 on success, 1 if the file system cannot be
     made, and 2 for a usage error.

EXAMPLES
     A V1 floppy of 360K and a V3 image of 64 megabytes:

           $ newfs_minixfs -V 1 -s 360 floppy.img
           $ newfs_minixfs -V 3 -s 16384 disk.img

     An image of a directory, just large enough, owned by root:

           $ newfs_minixfs -V 2 -d tree -o 0:0 tree.img

     An image of a MINIX build, with the owners, modes and devices of its
     METALOG:

           $ newfs_minixfs -V 3 -d destdir -F destdir/METALOG \
               -P destdir/etc -x usr.img
