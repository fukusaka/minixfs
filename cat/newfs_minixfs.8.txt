NAME
     newfs_minixfs – make a MINIX file system, empty or from a directory

SYNOPSIS
     newfs_minixfs -V version [-N] [-B le | be] [-b block-size] [-d directory
                   [-F specfile [-P dbdir [-x]]] [-o uid:gid]] [-i inodes]
                   [-l name-length | flex] [-m minix | linux | bytes]
                   [-s blocks] [-t time] [-z log-zone-size] image

DESCRIPTION
     newfs_minixfs makes a MINIX file system of version 1, 2 or 3, or one of
     Minix-vmd, in the file or device image; see minixfs(5).  It holds an
     empty root directory or, with -d, a copy of a directory.  The first 1024
     bytes of image, where a boot block may be, are left alone.  The file
     system is marked clean.  The image is locked with fcntl(2) while it is
     written, and one that another program holds is refused.

     The size comes from -s, which also makes the image file or cuts it to
     that size, or else from the size of an existing file.  With -d and
     neither, the image is made just large enough for the tree.

     The options are:

     -V version
             The version of the file system: 1, 2 or 3.  It has to be given.

     -N      Print the layout, and with -d what the tree needs, and write
             nothing.

     -B le | be
             The byte order: little-endian, as on the PC and the default, or
             big-endian, as on the Atari ST, the Amiga and the Macintosh.

     -b block-size
             The block size of V3, a multiple of 1024 up to 32768; 4096 by
             default, the smallest that MINIX 3 mounts.  V1 and V2 always have
             blocks of 1024 bytes.

     -d directory
             Copy directory into the file system: its files, directories,
             symbolic links, devices and pipes, preserving modes, owners and
             times.  Entries are sorted by name for reproducible images.  Hard
             links stay links, blocks of zeros stay holes, and symbolic links
             get the mode 0777, as MINIX and Linux give them.  The root
             directory takes the mode, owner and times of directory itself.
             Sockets are left out with a warning.  Existing device files can
             be copied without root privileges.

             Everything is checked before anything is written: names too long
             for the file system, owners, groups and device numbers too large,
             a link count too large, and room, counting holes as data.  What
             is wrong is listed, and nothing is written.  Without -i, the file
             system gets inodes enough for the tree.

     -F specfile
             Read the mtree(8) specification specfile as the -F option of
             makefs(8) of NetBSD does, in the hierarchical form and in the
             form with full paths of the METALOG that a build writes.  An
             entry sets the type, mode, owner, group, time, link target and
             device number of what it names, overriding the file in directory.
             A file missing from directory is created from its entry.  The
             entry must specify the type, mode, owner and group, plus the
             target for a symbolic link or the device number for a device
             file.  Regular files are created empty.  A missing file whose
             entry is marked optional is left out.  A type that differs from
             that of the file in directory is an error.  The keywords type,
             mode (in octal), uid, uname, gid, gname, time, link, device and
             optional are used; checksums, size, flags, tags and the like are
             ignored.  /set, /unset, continued lines and the escapes of vis(3)
             are understood; names with patterns are not.

     -P dbdir
             Look up the user names of -F in master.passwd or passwd, and the
             group names in group, of the directory dbdir, rather than in
             those of the system.

     -x      Copy only what the specification of -F names.

     -o uid:gid
             Give every file of the tree the owner uid and the group gid,
             numbers both.  A V1 inode keeps its group in one byte, so a tree
             with groups above 255 needs this in V1.

     -i inodes
             The number of inodes, rounded up to fill the blocks of the inode
             table; by default one for about every three blocks, or more if
             the tree of -d needs them.

     -l name-length | flex
             The length of names in V1 and V2: 14, as in MINIX and the
             default, or 30, the extension of Linux, which has magic numbers
             of its own.  V3 names are always 60 characters.  flex makes a V1
             or V2 file system of Minix-vmd, whose flex directories hold names
             of up to 60 characters, as its mkfs makes one: with the magic
             number of names of 14, the super block of Minix-vmd, and the bits
             of the maps past the last inode and zone clear.

     -m minix | linux | bytes
             The maximum file size in the super block: what MINIX works out
             from the zones that the double indirect zone reaches, the
             default, so that MINIX reads every file in full; what mkfs.minix
             of Linux writes, 2147483647 in V2 and V3; or bytes, from 1 to
             2147483647.  Linux and the tools of this package keep files to
             it; see minixfs(5).

     -s blocks
             The size in blocks.

     -t time
             The time of the root directory, in seconds since the Epoch, for
             images that must come out the same each time.

     -z log-zone-size
             A zone of 2 to the power of log-zone-size blocks; 0, one block,
             by default.  MINIX 3 after 3.3.0 does not mount a file system
             with zones of more than one block; see minixfs(5).

EXIT STATUS
     newfs_minixfs exits with 0 on success, 1 if the file system cannot be
     made, and 2 for a usage error.

EXAMPLES
     A V1 floppy of 360K and a V3 image of 64 megabytes:

           $ newfs_minixfs -V 1 -s 360 floppy.img
           $ newfs_minixfs -V 3 -s 16384 disk.img

     An image of a directory, just large enough, owned by root:

           $ newfs_minixfs -V 2 -d tree -o 0:0 tree.img

     An image of a MINIX build, with the owners, modes and devices of its
     METALOG:

           $ newfs_minixfs -V 3 -d destdir -F destdir/METALOG \
               -P destdir/etc -x usr.img
